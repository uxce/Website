// 003 INBIOME DISCLOSED ▶
RED TEAM CYBER SEC HUNTING

inBiome is a Dutch medical research company developing a diagnostic platform called Antoni, which analyses bacterial infections from patient samples within a few hours. Their platform consists of a Flutter-based web app, two FastAPI backends, and a WordPress site.

During reconnaissance I extracted the Flutter JavaScript bundle from the Antoni web app at antoni-research.inbiome.com. Deobfuscating main.dart.js revealed a list of internal API endpoints that weren't publicly documented including one that caught my attention immediately: GET /v1/lab_flow_web/organizations I sent an unauthenticated request to both API backends.

curl -s https://lf-research-api.inbiome.com/v1/lab_flow_web/organizations
curl -s https://fa-research-api.inbiome.com/v1/users/organizations

Both returned full JSON responses without requiring any authentication exposing a list of client organization names. These were real hospital and research institution names the kind of client relationships a medical device company would reasonably want to keep confidential.

The issue was a missing authentication check on two endpoints that the OpenAPI spec declared as protected. The spec said OAuth2PasswordBearer was required, but the actual server never enforced it.

After disclosing the information inBiome acknowledged the finding and patched both endpoints within the same reporting cycle. Subsequent testing confirmed the endpoints now correctly return 401 for unauthenticated requests.
